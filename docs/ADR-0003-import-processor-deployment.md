# ADR-0003: Import processor deployment boundary

Status: accepted and implemented

## Context

Local imports must pass untrusted files through the restricted processor. The existing processor runner starts a short-lived, digest-pinned container with no network, a read-only root filesystem, dropped capabilities, bounded resources, and narrowly scoped input/output mounts.

The Compose worker is itself a container. Giving it the Docker socket or a privileged container runtime would let a parser compromise become host control and would invalidate the isolation boundary. Paths inside the worker also cannot safely be passed as host bind-mount paths to the Docker daemon.

## Decision

The importing feature depends on the injected `ImportContentProcessor` contract. The feature owns durable staging, owner-scoped duplicate decisions, restart recovery, reports, and atomic catalogue publication. A deployment adapter owns materializing an immutable input in a private workspace, invoking `detect-file`, inspecting a ZIP before `extract-zip`, detecting each accepted member, and returning fresh member streams to the feature.

For the MVP deployment, that adapter must run in a host-side supervisor or an equivalently isolated job-runtime service with a narrow authenticated protocol. It alone may access the container runtime. API and general worker containers must not receive the Docker socket, broad host mounts, network access to an unrestricted Docker API, or additional Linux capabilities.

The adapter preserves the processor runner restrictions and deletes its private workspace after each attempt. Requests and results use stable request and file keys so a retry can compare output with already-persisted report rows.

The supervisor runs as a host process. Native Linux/production deployments use an authenticated Unix-domain socket. Docker Desktop cannot connect to a Unix socket bind-mounted from a macOS host, so the development deployment uses a loopback-only TCP listener plus a fixed dual-network bridge. The bridge forwards opaque bytes between the internal worker network and Docker's host gateway; it receives no authentication secret, Docker socket, configurable destination, or application storage. Authentication remains end to end between worker and supervisor. The worker does not see the Docker socket or a host path accepted as request input. Request bytes are streamed into a supervisor-created `0700` workspace; generated bytes return in bounded, checksummed frames and are staged in a worker-private `0700` response workspace. Neither side buffers whole model archives in memory.

The wire protocol allowlists `detect-file`, `extract-zip`, and `generate-preview`. It fixes all container paths, rejects unknown request fields, caps the JSON frame size, input bytes, output bytes, concurrency, ingestion duration, and processor execution duration, and authenticates with a deployment token. The supervisor invokes only an immutable `sha256:` image ID or `name@sha256:` image digest. Processor containers continue to have no network, a read-only root, dropped capabilities, `no-new-privileges`, a non-root UID, and CPU, memory, PID, and temporary-workspace limits.

Archive and preview output use a writable bind at `/output`; the processor creates the operation-specific `/output/archive` or `/output/preview` child. This keeps the archive destination absent before extraction and avoids mounting an already-existing directory at the child path.

## Consequences

- The feature implementation can be tested with a deterministic injected boundary and does not depend on container-runtime details.
- Native deployments may mount the supervisor socket read-only into the worker. Docker Desktop development uses the fixed TCP bridge because host Unix socket mounts return `ENOTSUP`. The host supervisor remains the only process with container-runtime access.
- M07 and C05 composition can use the typed supervisor client. The client transfers bytes rather than host paths and verifies every returned output checksum before exposing a stream.
- The supervisor is deliberately not a general command-execution service. It allowlists the versioned processor operations and fixed mount paths only.
- A compromised worker can submit allowed processor work or cause denial of service, but cannot issue arbitrary Docker commands or choose host mounts. Rotate the token if its confidentiality is lost.
